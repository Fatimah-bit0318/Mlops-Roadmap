# Day 12 - Monitoring, Drift and Retraining

## Objective
Learn the difference between infrastructure/application monitoring and ML monitoring, then simulate data drift, prediction drift, concept drift, and model performance degradation locally.

## Project structure

```text
Day12/
├── data/
│   ├── training_data.csv
│   ├── baseline_evaluation_data.csv
│   ├── data_drift_data.csv
│   └── concept_drift_data.csv
├── generate_data.py
├── train.py
├── monitor.py
├── requirements.txt
├── .gitignore
└── README.md
```

The CSV files are generated by `generate_data.py`.

## Setup in Windows PowerShell

Open the VS Code terminal in the `Day12` folder.

```powershell

.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, run this in the same terminal and activate again:

```powershell

.\venv\Scripts\Activate.ps1
```

## Run the project

Run each command from the Day12 folder:

```powershell
python generate_data.py
python train.py
python monitor.py
```

## What each script does

- `generate_data.py`: creates synthetic baseline, data-drift, and concept-drift datasets.
- `train.py`: trains a Logistic Regression fraud classifier and saves `model.joblib`.
- `monitor.py`: compares feature averages, compares prediction rates, and evaluates F1 using known ground-truth labels.

## Four concepts

1. **Data drift**: input feature distribution changes.
2. **Prediction drift**: model output distribution changes.
3. **Concept drift**: the relationship between features and the target changes.
4. **Performance degradation**: measured model quality falls; ground-truth labels are required.

## Monitoring worlds

**Infrastructure/application monitoring** checks CPU, memory, latency, errors, request count, disk and container health. AWS examples include CloudWatch Metrics, CloudWatch Logs, CloudWatch Alarms and CloudTrail.

**ML monitoring** checks input data, predictions, model quality and drift.

## AWS architecture mindset

```text
Endpoint
   |
Capture requests + predictions
   |
S3
   |
Scheduled analysis
   |
Compare against baseline
   |
CloudWatch metric/alarm
   |
Retraining trigger
```

This project simulates monitoring locally. It does not create a SageMaker endpoint, S3 bucket, CloudWatch alarm, EventBridge rule, or automatic retraining workflow. No AWS resources are created.

## Important limitation

The data is synthetic and designed for learning. Mean comparisons are a simple demonstration, not a robust statistical drift detector. Production systems should use suitable statistical tests, data validation, thresholds, monitoring windows, and human review before retraining.
